# OpenStack credentials for Cortex (prod)

`clouds.yaml` holds Keystone passwords, so it is **never committed**. It is generated:

```
openstack/clouds.yaml.tpl   tracked   everything except passwords ("@@NAME@@" placeholders)
infra/.env.prod             ignored   OS_READER_PASSWORD, OS_OPERATOR_PASSWORD
openstack/clouds.yaml       ignored   generated by render-clouds.sh
```

```bash
# 1. put the passwords in infra/.env.prod
OS_READER_PASSWORD=...
OS_OPERATOR_PASSWORD=...
CORTEX_OPENSTACK_HOST_DIR=/absolute/path/to/Cortex/openstack

# 2. generate (re-run after changing the template or a password)
./openstack/render-clouds.sh

# 3. restart the API so it re-reads the mounted file
cd infra && docker compose -f docker-compose.prod.yml -f docker-compose.security.yml --env-file .env.prod up -d api
```

The script refuses to run if `clouds.yaml` or `.env.prod` is not gitignored or is tracked.
To add a field (e.g. `cacert`) or a cloud, edit the `.tpl`; to add a secret, put a new
`"@@NAME@@"` in it and `NAME=...` in `.env.prod`.

File mode: the API container runs as uid 10001, so the generated file is `644` by default.
To tighten it: `sudo chown 10001 openstack/clouds.yaml && sudo chmod 600 openstack/clouds.yaml`
(re-rendering replaces the file, so repeat after each render).

If a real `clouds.yaml` was ever committed or pushed: rotate both Keystone passwords,
then remove it from history (`git filter-repo`) — deleting it in a new commit is not enough.
